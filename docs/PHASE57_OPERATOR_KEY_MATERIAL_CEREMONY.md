# Phase 57 — operator key-material ceremony

Phase 56 proved staged trust activation and key rotation, but creation of the real operator key material was still an external manual step. Manual key creation can leave private material with unsafe permissions, accidentally place it inside the source checkout, pair the wrong public/private files, or produce partial files after an interrupted procedure. Phase 57 closes that operational gap without embedding any production secret in the release.

## External bundle generation

The optional operator tool is:

```text
node scripts/manage_snapshot_operator_key.mjs generate OUTPUT_DIR LABEL
```

`OUTPUT_DIR` must resolve outside the application source checkout and must not already exist. Generation occurs in a temporary sibling directory and is promoted by a final directory rename only after the complete bundle verifies successfully. Existing destinations are never overwritten.

The bundle contains exactly four files:

- `snapshot-producer-private.pem` — Ed25519 PKCS#8 private key, mode `0600`;
- `snapshot-producer-public.pem` — Ed25519 SPKI public key, mode `0644`;
- `snapshot-producer-fingerprint.txt` — exact `ed25519-sha256:<hex>` key ID, mode `0644`;
- `snapshot-producer-ceremony.json` — canonical public ceremony record, mode `0644`.

No bundle generated by this tool is copied into the release checkout.

## Ceremony record

The public record binds:

- format/schema identity;
- producer role;
- operator label;
- SPKI-derived Ed25519 key ID;
- canonical SPKI public key bytes;
- source-checkout identity (`schemaVersion`, SHA-256, file count and total bytes) at generation time.

This lets the operator prove which exact reviewed checkpoint was used to initiate the ceremony before the trust-store mutation changes source identity.

## Verification

```text
node scripts/manage_snapshot_operator_key.mjs verify BUNDLE_DIR
```

Verification requires:

- bundle directory outside the source checkout and not a symlink;
- exactly the four expected regular non-symlink files;
- exact file modes (`0600` private, `0644` public artifacts);
- Ed25519 private/public key pair match;
- fingerprint exact match;
- canonical ceremony JSON and public-key match;
- current source-checkout identity equal to the ceremony record.

Any mismatch fails closed with exit 77 at the CLI boundary.

## Trust-store use

Phase 57 does not automatically trust a newly generated key. The intended reviewed flow remains:

1. generate/verify the external bundle on the exact checkpoint;
2. independently compare the printed/stored fingerprint through the operator's trusted channel;
3. stage the public key with `manage_offline_snapshot_trust.mjs stage`;
4. activate it with the external private key to produce Phase-56 proof of possession;
5. review/checkpoint the resulting source-controlled trust change;
6. only then produce a signed dependency snapshot.

The private key must remain outside the source checkout for its full lifetime.

## Current checkpoint state

The release production trust store remains empty. Phase 57 verifies the key-material ceremony with ephemeral test keys only. No production private key, public trust anchor or fabricated operator identity is embedded.
