Phase 66 — Fault Injection UI
- Adds the first browser Fault Injection panel over the deterministic Phase 65 Fault Engine Core.
- React/browser code does not reimplement fault semantics; pack verification, preconditions, mutation resolution, expected effects, negative controls, blast radius and rollback safety remain Fault Engine responsibilities.
- Runtime and Builder workflows share the same content-addressed built-in Fault Pack and core injection functions.
- Runtime preview is side-effect free and injection is permitted only after a SHA-256 preview token binds scenario hash, state revision, pack identity, fault ID, exact bindings, seed, mode and active overlay identity.
- Runtime injection records the entire resolved fault as one history step even when the fault contains multiple underlying Engine operations.
- Compatible Runtime faults may append to a single overlay; active overlay divergence fails closed before additional injection.
- Latest-fault rollback uses Phase 65 inverse operations and fails closed after later Runtime state changes.
- Builder mode creates an isolated draft Engine state; the healthy Builder source is unchanged while one or more faults are prepared.
- Persistent materialization occurs only through explicit Create faulted scenario variant action and produces an ordinary scenario-source with faultOrigin/canonical recovery.
- Builder source revision or compiled-hash drift invalidates the draft.
- UI displays the four declarative difficulty dimensions directly and does not invent an opaque scalar difficulty score.
- Full temporal/intermittent scheduling, generated multi-fault curricula and broad domain Fault Pack expansion are intentionally deferred.
