Phase 65 — Fault Injection Engine Core
- Adds deterministic, AI-free Fault Pack and Fault Overlay contracts.
- Healthy/imported scenario state remains reusable; injection returns new Engine state and an immutable overlay rather than mutating the baseline/source.
- Fault packs are exact-versioned and content-addressed with canonical SHA-256 identities.
- Faults declare named target bindings, accepted resource types, preconditions, incompatibilities, mutations, expected effects, negative controls, symptoms/hidden truth, recovery mode, blast-radius bounds, visibility policy, explicit difficulty dimensions, tags and learning objectives.
- Mutations resolve to ordinary Engine set/remove operations; seeded choice values are deterministic for the same uint32 seed + fault + mutation identity.
- Preconditions must be TRUE before mutation; expected effects and negative controls must be TRUE after mutation.
- Actual before/after Engine state is used to calculate changed-resource blast radius.
- Exact inverse operations are captured per mutation and test-applied before a fault is accepted as reversible.
- Latest-fault rollback fails closed if Runtime state changed after injection; existing Runtime history/checkpoints remain the safe recovery path in that case.
- Fault overlays bind exact scenario hash, pack locks, instance application hashes, seeds, bindings, resolved/inverse operations, revisions and changed resources; semantic verification detects internally rehashed instance tampering.
- SCENARIO_VARIANT overlays can materialize a new ordinary scenario-source without modifying the healthy source.
- Persistent variants bind faultOrigin and captured recovery operations; compiler preserves faultOrigin into normalized scenarios.
- Built-in starter pack: foundation.network.core@0.1.0 with routing.remove_default_gateway and firewall.force_default_deny.
- Full user-facing Fault Injection panel, temporal scheduler and broad domain fault library are intentionally not claimed in Phase 65.
