## What is supported today, exactly?

- **Five registered enterprise adapters:** `builtin.json`, `builtin.csv`, `builtin.tsv`, `builtin.xlsx`, `builtin.ods` in `enterprise-import/src/adapters.ts`. The structured adapter contract is not a guarantee that any arbitrary spreadsheet or JSON file can produce a correct network. The established Excel/CSV/TSV/ODS quick-import path `ui/src/browser/network-topology-import.ts` reads declared nodes and connections, then permits explicit Builder compilation/layout or modeled Runtime activation **when the imported source is sufficient**. Enterprise mapping/review/reimport is a separate existing path.
- **One native scenario source:** the `ui/src/browser/import-workbench.ts` / native JSON menu expects a YadiLab format/schema, not an arbitrary external JSON network export; it is not a sixth enterprise adapter.
- **Eight scoped specialized preview/review modules:** GraphML, draw.io, DOCX, ODT, Nmap XML, Nessus, Ansible YAML and Ansible INI. These **really have production parsers and UI**, but their **generic planned-profile registry entry remains BLOCKED** by design. GraphML has a source-bound, explicitly reviewed candidate path into the actual Compiler, layout and Builder; other seven profiles primarily expose read-only inspection/association/replay, **not** full network Builder creation. Nmap/Nessus observations are not present verified network state.
- **Thirteen registry-only profiles:** Visio VSDX, GNS3, EVE-NG, Cisco CML YAML, vendor configuration text, PDF digital tables, Terraform HCL/state, PCAP/PCAPNG, Windows EVTX, JSONL/text logs and static HTML tables. Filename recognition in `enterprise-import/src/planned-format-profiles.ts` is `BLOCKED` and is **not** a parser, UI import, or Engine/probe activation.
- **Not a completed universal import engine:** no arbitrary PDF/image/OCR auto-topology, Visio project interpreter, GNS3 emulator execution, live import reconnaissance, observed-result-to-Engine-TRUE promotion, or verified physical cable inference. Lack of provenance or an ambiguous connection must produce `UNKNOWN`/`UNMAPPED`/`REVIEW_REQUIRED`, not invented links or green checks.

The dedicated scripts and workflows are present in the tree, but their mere presence is **not** evidence of execution on every current main SHA.
2. `tests/enterprise-import/run_network_topology_import_checkpoint.mjs` asserts example CSV nodes, source-declared links only, no guessed connections from gateway/address, malformed IDs/endpoints/IP fail closed, and an XLSX example parser result. `tests/browser/run_network_topology_checkpoint_tests.mjs` verifies CSV source compilation and an Excel parser; it is *not* proof of visual E2E on every file type.

It does **not** prove the same complete path for arbitrary TSV, ODS, XLSX, DOCX or PDF uploads. An optional external Excel fixture is loaded only if `YADILAB_IMPORT004_TEST_XLSX` is explicitly supplied; do not mark that optional case PASS when absent.
4. The core release identity real-Chromium smoke `tests/acceptance/run_release_identity_real_browser.py` proves mounted browser identity/menus and spoof rejection. It is **not** equivalent to a successful file-selection and preview/review/Builder/probe lifecycle for every profile. ## Reconciliation of apparently contradictory status labels

- `planned-format-profiles.ts` advertises `IMPORT_PROFILE_NOT_IMPLEMENTED` for `.docx`, `.odt`, `.graphml`, Nmap/Nessus and Ansible when asked through the **generic planner**. This is correct: it does not register specialized imports. Existing dedicated modules are real but independently activated through their specific UI and review contracts.
- `enterprise-import/src/external-mapping.ts` labels `DOCX`, generic `YAML`, generic `XML`, and `PDF` as unsupported in the **generic enterprise baseline adapter**. This is likewise not a denial that separate DOCX tables or Ansible YAML or Nmap XML specialized *read-only* parsers exist.
- `ui/app/main.mjs` **does** display GraphML's explicit reviewed Builder candidate and actual compile/layout/transition, although its initial modal is titled "preview only"; never report GraphML as either universally blocked or unconditionally activated.
- Separate `SOURCE_BOUND_REPORT` replays attach reported original evidence to existing Builder identities. They are **not** file-to-network source import, not packet/probe execution, and not proof of real identity or physical connectivity.

## Acceptance oracles frozen for IC-010 and following checkpoints

- Profile discovery is **signature/structure/producer-version based** and bounded, with `.xml`/`.yaml` ambiguity denied; a mere suffix never activates a parser or scenario. Wrong magic bytes, DTD/XXE, zip bombs, embedded scripts, secrets, duplicate keys and oversized input must fail closed.
- The next shared UI entrypoint must show profile, source SHA-256, typed original locators and the exact `TOPOLOGY_DECLARED` / `CONFIG_DOCUMENTED` / `EVIDENCE_OBSERVED` truth class, and require explicit user consent before any Builder replacement. Existing CSV/Excel quick-import and GraphML safe reviewed Builder flow must remain available with **no regression**.
- Positive tests must cover each eligible file's *actual* supported source subtype, accurate mapped nodes/interfaces/only approved connections, compile/layout, Runtime modeled-probe eligibility and `TRUE`/`FALSE`/`UNKNOWN` based solely on existing Engine; separate evidence-only files must never become active network truth.
- Negative tests must prove source switch/cancel/race/invalid profile/changed Builder leaves active state untouched, no cross-profile XML/YAML selection, no HTML injection or metadata export of secrets, and no reports that confuse an older security scan with current reachability.
- CI gate: actual exact PR head checks, import probes and the new inventory test; independently successful exact-main Linux release and actual mounted Chromium; report separately whether dedicated format-specific file chooser was run. No manual Parrot request for tests already covered in Ubuntu Actions.
