## Reproduced source integrity failure
- `compiler/src/canonical-json.ts`: `normalizeJson` assigns an own JSON `"__proto__"` into ordinary `{}` with `output[key]=...`. On actual JavaScript objects parsed from JSON this silently changes clone prototype and drops own `__proto__` from `JSON.stringify`. A reproducible minimal collision is `canonicalJson(JSON.parse('{"__proto__":{"permission":"allow"}}')) === canonicalJson({})` under the old source. That violates source-to-identity uniqueness for JSON data.
- `compiler/src/helpers.ts`: `deepCloneJson` and `deepMergeObjects` assign arbitrary own keys into ordinary `{}`; additionally reading `out[k]` without `hasOwn` can use inherited `Object.prototype` during merge. Malicious `__proto__` input can alter the returned object's prototype or discard semantic input. No code should treat inherited values as declared profile defaults.
- `enterprise-model/src/canonical.ts`: equivalent `normalizedJson` and own-key-to-ordinary-object assignment can lose `__proto__` when canonically hashing Enterprise evidence. This is *not* yet a demonstrated full CI/release provenance bypass; it is a source-bound canonical data collision that must be fixed and regression tested.
