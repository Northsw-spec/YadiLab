## Problem
The existing P2b compares a live editable Builder/Runtime `ScenarioSource` against a producer-verified original input and returns non-mutating ADDED/REMOVED/CHANGED/UNCHANGED counts. A user may export those **aggregates** for later reference, but a saved file is not authoritative: source bytes, workspace revisions, link-source decisions and even previous P2b review consent can change. Imported sidecars must be treated as **untrusted input** and must not directly activate Builder, Runtime, probes or previously approved replacements.

## P2c1 exact bounded contract (frozen before any code)
1. Introduce a versioned, **data-minimizing, canonical-only** JSON sidecar derived exclusively from a fresh P2b read-only report; `formatId=yadilab.core-network-reimport-review.v1`, `schemaVersion=1`, `status=REVIEW_ONLY`, `canActivate=false`, `engineVerified=false`, `physicalTopologyVerified=false`. Only typed current-live-workspace semantic SHA, incoming original-file SHA+byte size, source decision `LINKS_SHEET` or `INLINE_CONNECTED_TO` if present, original workspace mode/revision, exact 4-count resources/connections. No source names, host/IP, cell content, raw locators, paths, credentials, timestamps, old-file hash claims, arbitrary diagnostics or automatic decisions. Deterministic serialization from exactly validated source data; full record and nested counts `Object.freeze`d and immutable.
2. Import sidecars only through the existing reimport UI using a distinct native **`.json` report picker**, never the five-format network source chooser or model import. Strict basename, max **16 KiB before and after reading**, UTF-8 decoder fatal, JSON object strict exact allowed keys (no unexpected/private/prototype keys), 64-lowercase hex SHA, positive bounded safe byte length, bounded revision+count integers, exact status and false safety flags. Error returns one fixed `IC020_P2C1_SIDECAR_INVALID` or `IC020_P2C1_REPLAY_MISMATCH`; never show raw parser errors/sidecar text. No external network or file system reads outside user-selected files.
3. Replay requires an **already selected and producer-reviewed new original document**, its previously selected exact P2a source choice if conflict, plus **fresh actual original-byte reparse** using P1 `verifyNetworkTopologyOriginalForActivation`. Recompute P2b report from **current live Builder/Runtime** (not claimed old source bytes) and demand exact agreement between imported sidecar, fresh live comparison and original SHA, byte count, source decision and all counts. Source switch, changed workspace/revision, expired pending read, cancel, Escape/reopen must reject, leaving Builder/Engine unchanged.
4. After successful replay, the UI reports `MATCHED_REVIEW_ONLY` and must reset `reimportApproved=false`; no auto-approval and both Builder/Runtime activation actions stay disabled until the user separately clicks the existing **Approve replacing the entire current workspace** button (or explicitly repeats ordinary P2b review); P1 last-moment source replay and P2b live Builder digest comparison are still enforced at activation. Avoid any UI state that allows a discarded saved report to approve a new source.
5. Provide `Download read-only reimport report JSON` only after a P2b reviewed comparison and while current Builder identity is still the reviewed one; never embed sensitive source data. The sidecar is informational only, not a cryptographic signature or verified physical topology.
