# ODT-P5 — frozen bounded multi-reference acceptance contract

Authoritative source at entry: GitHub main `9c0cae57791105638ce926f1d2cb968c68850852`, tree `892b66ddb1a2fa2a692f3ed8d98bb5a20a4892c7`. This PREP contract is saved **before coding**. Existing ODT-P1/P2 strict OASIS package/table parser, P3 source-bound single-cell consent, P4 zero-content one-reference sidecar are already verified in current main and must not regress.

## Output and truth boundary

An operator may add **2–10** individually P3-revealed, P4-acknowledged ODT cells to a temporary metadata-only review queue and explicitly export **one** bounded JSON report. One source file, one Builder scenario + sourceRevision; each original typed cell locator is unique, each target existing Builder resource ID is unique. Each cell still requires fresh per-cell P3 permission and P4 *separate* unchecked permission; staging is explicit. Final export requires a **third, separately unchecked acknowledgement**. Queue must NEVER store raw cell text, snippets, per-cell hashes or ZIP bytes.

Fixed new format `yadilab.odt-reviewed-multi-references`, `schemaVersion: 1.0.0`, `status: REVIEWED_ASSOCIATIONS_ONLY`, `engineVerified:false`, `physicalTopologyVerified:false`. Sidecar includes original ODT **file-level** SHA256, `office.odt-tables.structural.v1`, typed cell `odt-table-cell` locators / `content.xml`, scenarioId/sourceRevision, existing selected resource IDs, and assertion `USER_ASSERTED_ASSOCIATION_NOT_VERIFIED`. No source cell contents or value-level hashes, no physical links, no network observation/Engine PASS, no scenario import, no Builder changes.

## Security gates

- Before staging each cell: re-read the browser-selected ORIGINAL ODT file and re-run full P3 ZIP/mimetype/manifest/XML, SHA256/locator and secret screening; require currently disclosed text, locator and source SHA to match. Then rerun existing **pure P4** against the current Builder snapshot; stage only the P4 metadata sidecar. Source switch (including same filename) and modal unmount clear all queued records; selection change clears *current* P3/P4 consent but retains already reviewed metadata-only queue.
- Before final export: for **every** queued locator, re-read original source file, rerun full P3 and P4 against current Builder; verify regenerated P4 sidecar is exactly identical to staged metadata and that source file SHA/revision/targets have not changed; **atomic fail** if any is stale, removed, sensitive, invalid or duplicate. Test that no partial download occurs.
- Pure standalone P5 domain validation must reject wrong/unexpected fields, elevated trust flags, different source SHA/scenario/revision, bad/prototype resource IDs, duplicate target or source cell, out-of-bounds ordinals, unsupported source schema, fewer than 2 or more than 10, revoked final consent, and stale Builder. All stable error codes, no raw content in diagnostics.
- Final report is deterministic sorted by table/row/cell ordinal, and contains only minimum exact typed locators and selected existing modeled resource IDs. Never auto-match by hostname/address. P3 credential heuristic is not a guarantee of complete secret detection.
- No localStorage/IndexedDB, server upload, network fetch or mutation of Builder/Engine; React text nodes escape document values. Queue displays only ordinal coordinates and resource IDs. New source/file clears queue and consent; closing/reopening clears all; removing below 2 disables export.
- Existing ODT P1-P4 & DOCX P2-P6, GraphML, Nmap, Ansible and broad import GitHub CI exact PR head SUCCESS required. Actual compiled-app Chromium must stage 2 independently consented cells on distinct resources, check P5 JSON no content, block sensitive cell, deny missing final consent, verify source switch/removal/reset, exact canonical Builder JSON before/after, no cross-origin calls/JS errors. Exact merged-main Linux release completed SUCCESS with artifact required. Ubuntu GitHub Actions sufficient; no manual Parrot test requirement.

**Standards & design basis**: OASIS OpenDocument v1.3 package https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part2-packages.html ; OASIS ODF table schema https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part3-schema.html ; OWASP file validation https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html ; current-main DOCX-P5 metadata-only reporter (as pattern), independent ODT-P3/P4 authoritative source.

**Not supported**: automatic row expansion, arbitrary ODT rich text/complex tables, bulk value reveal, asset identity verification, physical network discovery, cross-document merges, or network configuration modifications.
