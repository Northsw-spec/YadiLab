# CONVERGENCE — synthetic, area-scoped OSPFv2 LSDB retention and aging

## Source authority, RFC and preconditions

- Canonical protected GitHub `main=ca56ae6d5b6da9064189a08522dcc5f1919cb147`, tree `ae58c2ed0f7ae51dcc1d7d7c41e69aa36e4f347f` at checkpoint start. No historical ZIPs have source-code authority.
- [RFC 2328 §12.2](https://www.rfc-editor.org/rfc/rfc2328.html#section-12.2), [§13.1](https://www.rfc-editor.org/rfc/rfc2328.html#section-13.1), [§13.2](https://www.rfc-editor.org/rfc/rfc2328.html#section-13.2), [§14](https://www.rfc-editor.org/rfc/rfc2328.html#section-14) and Appendix B constants. MinLSArrival is 1 second for a new instance replacing a recently installed **flooding-sourced** database copy; MaxAge is 3,600 seconds; a MaxAge LSA cannot be used for SPF and must not be blindly removed while any neighbor requires retransmission or remains in Exchange/Loading.
- The area is **derived from the enclosing OSPF packet**, not from the LSA itself (RFC §13). This new sidecar accepts only **synthetic, caller-assigned area observations**; it neither parses real OSPF packet headers nor verifies any cryptographic, neighbor, physical or network source. The `FLOODING_MODEL` and `SYNC_MODEL` source labels are model-supplied assertions and explicitly **not proofs of actual packet receipt**.

## Pure, bounded area LSDB model

Files: `engine/src/ospf-area-lsdb.ts`, public exports `engine/src/index.ts`, tests `tests/engine/run_ospf_area_lsdb_tests.mjs` and documentation here. Existing LSA body parser, DD, LSR, Loading coordinator and EngineState are unchanged.

- A snapshot is bound to the exact `scenarioId`, `scenarioHash`, `stateRevision`, `ownerResourceId` of an existing `network.router` and a canonical IPv4 area ID, plus a nonnegative virtual millisecond clock. Different area IDs use separate independent sessions. Exact Engine or source/area mismatch fails closed.
- Store at most **128** Type 1/2 LSA identities `(LS type, Link State ID, Advertising Router)`; a transaction accepts at most **8** full raw LSAs (existing byte ceiling 4,096 each), each re-verified by **Fletcher**, complete Router/Network body rules and exact header semantics. All stored entries are canonical identity-sorted, defensively byte-copied and have a source label and installation/receipt timestamp. Invalid entry bytes or changed header metadata fail inspection before any operation.
- `receiveOspfAreaLsaBatch` validates all inputs and identities before doing any state changes; a bad member, duplicate identity, wrong area, stale revision, over-capacity or unmodeled MaxAge orphan fails **atomically** with the exact unchanged original state. Older/equivalent valid LSA instances are ignored and separately traced; no unearned new content is installed.
- RFC §13.1 recency uses **signed** LS sequence first, then **unsigned** LS checksum, MaxAge precedence, and age delta strictly greater than 900 seconds (younger wins). The model reuses `compareOspfLsaHeaders` rather than inventing ordering. If recency compares equivalent but non-age bytes differ, fail closed on a same-instance checksum collision.
- If the stored existing LSA's `source=FLOODING_MODEL` and it was installed less than `MinLSArrival=1000ms` ago, discard an otherwise newer replacement and emit `LSA_MIN_LS_ARRIVAL_DISCARDED`. At 1000ms exactly a replacement can proceed. The condition depends on the **existing record's source**, not on the incoming source. `SYNC_MODEL` is only a synthetic peer-snapshot receipt category, never permission to bypass a recent flooding-sourced stored record.
- The original LSA byte array is **never mutated** for aging. At virtual time `t`, effective LS age is `min(3600, original LS age + floor((t-install time)/1000))`. Every read returns explicit `currentAgeSeconds` and `maxAgeBlocked`; crossing MaxAge emits `LSA_MAXAGE_REACHED_MODEL` once, not on every subsequent timer advance. A newer MaxAge instance of an existing identity is retained and signaled with `LSA_MAXAGE_RETAINED_MODEL`.
- **No automatic purge.** RFC §14 requires both no neighbor retransmission-list references and no neighbors in Exchange/Loading before removal. These prerequisites are not independently modeled here. For the same reason, an orphan MaxAge receipt with no database copy is refused as `OSPF_AREA_LSDB_MAXAGE_ORPHAN_UNMODELED`: RFC §13 requires otherwise-unknown neighbor/ack state. Keeping such behavior unmodeled is safer than pretending to acknowledge/discard or flush.
- This is an **in-memory, serializable, source-bound LSDB snapshot model**. `LSA_STAGED_MODEL` and `LSA_REPLACED_MODEL` mean deterministic model updates, **not** a verified on-wire flood, real LSDB installation, neighbor acknowledgment, actual route computation, SPF, link-state integrity authority, Full adjacency or saved persistent file.
- All operations leave the EngineState, topology, firewall, reachability and routing table entirely unchanged.

- Independent fixed Fletcher byte vectors and test-only checksum resealing, two-area separation, RFC recency precedence, older/duplicate handling, MaxAge aging and no unsafe purge, exact 999/1000ms boundary, early snapshot receipt after flooded copy, source hash/Engine revision spoof rejection, wrong area, damaged checksum, invalid Router LSA flags, forged header fields, corrupt stored byte, duplicate identities and 128-entry capacity. 1,000 byte-identical multi-operation synthetic replays, unchanged Engine reachability oracle.

## Required future checkpoints

An independently verifiable neighbor and packet admission model, Link State ACK and retransmission lists, flooding and MaxAge flush proofs, self-origination / MaxSequenceNumber behavior, explicit multi-area and AS-external scope rules, SPF graph validation (including bidirectional links and transit DR), schedule/recalculate rules and route truth tests. Until then, never promote saved LSA metadata or `REQUESTS_SATISFIED_MODEL` to actual `FULL` or live routing.
