## Exact source-grounded failures
1. `enterprise-import/src/delimited.ts`: CSV/TSV dynamic headers are untrusted strings and stored in ordinary `{ }` using `fields[header] = ImportCell`. An own header `__proto__` activates inherited object prototype setter instead of retaining an own cell, and creates inherited `value`, `locator` rather than a real mapped field. Source data/provenance can be silently lost or misinterpreted. A `constructor` or `toString` header must remain an own literal field. Do not ban untrusted names merely to avoid the bug.
2. `enterprise-import/src/json.ts` similarly writes untrusted JSON record fields into ordinary `{}` in both root-object and array-of-records pathways. Parsed JSON own `__proto__` is meaningful source data and must be preserved; JSON Pointer provenance must be exact and escape `/` and `~`.
3. `enterprise-import/src/tabular.ts`: shared XLSX/ODS physical-row mapper stores untrusted header names via ordinary dictionary assignment. Same `__proto__` setter and discarded original header; use actual shared `PhysicalRow` mapper in tests, not claim full workbook ZIP was run in this test. Existing dedicated XLSX/ODS real archive regressions remain unchanged.
4. CSV/TSV quote state machine in `delimited.ts` permits invalid data after a closing quote (e.g. `"node"junk,ip`), mistakenly concatenating `junk` or re-entering quote mode; reject as `IMPORT_MALFORMED_QUOTE` without echoing raw payload. Valid RFC-style quoted values, escaped `""`, delimiter/newlines and quoted multiline remain accepted. Never treat malformed line as validated topology.
