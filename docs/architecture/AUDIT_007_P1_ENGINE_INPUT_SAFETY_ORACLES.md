## Source-grounded bugs to reproduce
1. In `parseIpv6`, empty hextets from `leftRaw.split(':').filter(Boolean)` and `rightRaw.split(':').filter(Boolean)` are dropped without verifying syntax, e.g. `2001:db8:::1`, `:1::2`, `2001:db8::1:`. These malformed addresses currently can be returned as if valid. Fix by preserving split boundaries and rejecting any interior empty segment beyond the one valid `::` compression marker.
2. In `parseIpv4`, `String(n) !== String(Number(part))` compares an integer to itself. Leading-zero octets (e.g. `192.168.001.1`) are therefore accepted without canonical decimal grammar. Reject octets with leading zero (except literal `0`); keep 0, 255, valid subnet hosts and IPv4-embedded IPv6 forms.
3. In `parseCidr`, `Number('') === 0` can convert an empty `/ ` prefix into a wildcard `/0`. Reject missing/whitespace/sign/hex/float/exponent/leading-zero prefix strings; accept exact canonical `0..32` or `0..128`. Preserve no-slash exact host forms and valid default `0.0.0.0/0`, `::/0`. These predicates feed Engine ACL and routing; no invented TRUE from invalid selector.
4. In `deepCloneJson`, assigning untrusted own JSON keys into `{}` with `out[key] = ...` makes an own `"__proto__"` key mutate the clone's prototype instead of becoming an own JSON field. Test a real `JSON.parse('{"__proto__":{"trusted":true},"a":1}')` value: clone must have Object.prototype as prototype, preserve own `__proto__` and not inherit `trusted`, while preserving ordinary keys, arrays, nested JSON and read-only path restrictions. Use own data properties (e.g. `Object.defineProperty`), not prototype-mutating assignment. No global Object.prototype pollution or automatic Engine success should be claimed.
